# SESPORT — Production Telegram Bot Development Specification

## 1. ROLE

Act as a **Senior Python Backend Engineer, Django Architect, Telegram Bot Developer, Database Designer, and DevOps Engineer**.

Build a complete, production-ready Telegram Bot called **SESPORT** using:

* Python 3.11+
* Django 5.x
* Django Admin
* Aiogram 3.x
* Asyncio
* FSM (Finite State Machine)
* PostgreSQL
* Redis
* Django ORM
* aiogram
* python-dotenv / environment variables
* Docker + Docker Compose
* Webhook-ready architecture
* REST API layer where necessary
* Proper logging
* Error handling
* Security best practices

The project must be written as a **real production application**, not as a simple demonstration or single-file Telegram bot.

Do NOT put all code into one file.

Use a clean modular architecture with separation of concerns.

---

# 2. PROJECT PURPOSE

SESPORT is a consumer-protection Telegram platform.

The system allows consumers to:

* Submit complaints about expired or defective products.
* Upload product evidence/photos.
* Send the store's GPS location.
* Track complaint status.
* Check nearby stores.
* View store safety ratings.
* Track cashback/rewards.
* Read consumer rights information.
* Contact support.

The system must also provide an **administrator/moderator interface through Django Admin**.

Administrators must be able to:

* View users.
* View complaints.
* Moderate complaints.
* Change complaint statuses.
* View uploaded evidence.
* View complaint locations.
* Manage stores.
* Manage store safety ratings.
* Manage cashback/rewards.
* Manage consumer rights content.
* Manage support information.
* View basic system statistics.

# 6. COMPLAINT FSM

Implement the complaint process using **Aiogram 3.x FSM**.

When the user clicks:

```text
📝 Shikoyat qilish
```

start the FSM.

## State 1 — Complaint Description

Send:

```text
Mahsulot haqida batafsil tasnif kiriting:
```

Accept text input.

Validate:

* Text must not be empty.
* Minimum recommended length: 10 characters.
* Maximum length: 3000 characters.

Save the text into FSM state.

Then transition to:

```text
ComplaintStates.waiting_for_photo
```

---

# 7. STATE 2 — PHOTO

Send:

```text
Mahsulot va uning amal qilish muddatini tasdiqlovchi rasmni yuboring:
```

Accept only Telegram photo messages.

If the user sends anything other than a photo:

```text
Iltimos, mahsulotning aniq rasmini yuboring.
```

When a valid photo is received:

* Save Telegram `file_id`.
* Store it in FSM state.
* Optionally download/store the file through a service layer if required.
* Transition to location state.

Do NOT unnecessarily duplicate Telegram files.

# 21. DJANGO ↔ AIOGRAM ARCHITECTURE

Do NOT tightly couple Telegram handlers with Django models.

Use service layers.

For example:

```text
bot/
    services/
        user_service.py
        complaint_service.py
        store_service.py
        cashback_service.py
        notification_service.py
```

Handlers should call services.

Example architecture:

```text
Telegram Update
       ↓
Aiogram Router
       ↓
Handler
       ↓
Service Layer
       ↓
Django ORM
       ↓
PostgreSQL
```

Keep business logic outside handlers whenever practical.

---

# 22. ASYNC DATABASE OPERATIONS

Aiogram handlers are asynchronous.

Use Django's async ORM capabilities where appropriate.

Avoid blocking operations inside async handlers.

If synchronous Django functionality must be used, safely wrap it using:

```python
sync_to_async
```

or the appropriate Django async mechanism.

Never block the event loop.
